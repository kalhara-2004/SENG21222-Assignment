# Product Sales Report Generator

## SENG 21222 – Software Construction

This project was developed as part of **Assignment 1 – 2026** for the **SENG 21222 – Software Construction** course at the **University of Kelaniya, Sri Lanka**.

The project is a Java command-line application that reads daily product sales data from a CSV file, calculates a sales summary, and generates a formatted report.

The generated report can either be displayed in the console or saved to a text file.

---

## Project Features

The application provides the following functionality:

- Reads product sales data from a CSV file.
- Calculates total revenue for each product.
- Calculates total revenue for each category.
- Identifies the best-selling product based on quantity sold.
- Identifies the product with the highest revenue.
- Calculates the grand total revenue.
- Displays the sales report in the console.
- Saves the sales report to a text file.
- Handles common input and file-related errors.
- Supports command-line arguments.
- Provides interactive output selection when required.
- Uses Object-Oriented Programming principles.
- Uses the Strategy Design Pattern for report output.
- Applies SOLID principles where appropriate.
- Includes unit testing for important sales calculation logic.

# Main Components

## Product.java

The `Product` class represents an individual product sales record.

It stores information including:

- Product ID
- Product name
- Category
- Quantity sold
- Unit price

The product information is used to calculate the total revenue generated by each product.

The revenue of a product is calculated using:

```text
Total Revenue = Quantity Sold × Unit Price
```

---

## CsvReaderService.java

The `CsvReaderService` class is responsible for reading product sales information from the CSV file.

Its main responsibilities include:

- Opening the specified CSV file.
- Reading product sales records.
- Skipping the CSV header row.
- Processing the CSV columns.
- Creating `Product` objects from the CSV records.
- Handling invalid or incomplete CSV data appropriately.

---

## SalesCalculatorService.java

The `SalesCalculatorService` class contains the main sales calculation logic of the application.

It is responsible for calculating:

- Revenue for each product.
- Revenue for each category.
- Best-selling product.
- Highest-revenue product.
- Grand total revenue.

After performing the calculations, the results are stored in a `SalesSummary` object.

---

## SalesSummary.java

The `SalesSummary` class stores the calculated sales information.

It contains information such as:

- Products included in the report.
- Revenue for each category.
- Best-selling product.
- Highest-revenue product.
- Grand total revenue.

This allows the calculation logic and output logic to remain separate.

---

## OutputStrategy.java

`OutputStrategy` defines a common interface for different report output methods.

The project uses the **Strategy Design Pattern** so that different output methods can be implemented independently.

The current implementations are:

```text
OutputStrategy
       |
       +-- ConsoleOutputStrategy
       |
       +-- FileOutputStrategy
```

This design improves extensibility because another output strategy could be introduced without changing the core sales calculation logic.

---

## ConsoleOutputStrategy.java

The `ConsoleOutputStrategy` class is responsible for displaying the generated sales summary report in the console.

The console report contains:

- Revenue per product.
- Revenue per category.
- Best-selling product.
- Highest-revenue product.
- Grand total revenue.

---

## FileOutputStrategy.java

The `FileOutputStrategy` class is responsible for writing the generated sales summary report to a text file.

The required output file can be specified when file output is selected.

---

## SalesReporter.java

`SalesReporter` is the main entry point of the application.

It coordinates the other components of the program.

Its responsibilities include:

- Processing command-line arguments.
- Determining the CSV file path.
- Determining the selected output method.
- Providing interactive output selection when required.
- Creating the appropriate output strategy.
- Calling the CSV reader service.
- Calling the sales calculator service.
- Passing the calculated summary to the selected output strategy.
- Handling application errors.

---

## SalesCalculatorServiceTest.java

`SalesCalculatorServiceTest` contains unit tests for the sales calculation functionality.

The tests are used to verify important application logic, including:

- Revenue calculation.
- Best-selling product detection.

Unit testing helps ensure that the core calculation functionality behaves as expected.

# CSV Input Format

The program reads product sales data from a CSV file.

The expected columns are:

```csv
product_id,product_name,category,quantity_sold,unit_price
```

Example:

```csv
product_id,product_name,category,quantity_sold,unit_price
P001,Wireless Mouse,Electronics,12,25.50
P002,Notebook,Stationery,35,3.75
P003,USB Hub,Electronics,8,18.00
P004,Ballpoint Pen,Stationery,100,0.50
P005,HDMI Cable,Electronics,20,12.00
```

### CSV Column Description

| Column | Description |
|---|---|
| `product_id` | Unique identifier of the product |
| `product_name` | Name of the product |
| `category` | Category of the product |
| `quantity_sold` | Number of units sold |
| `unit_price` | Price of one unit |

# Calculations

## 1. Revenue Per Product

Revenue for each product is calculated using:

```text
Revenue = Quantity Sold × Unit Price
```

Example:

```text
Product       : Wireless Mouse
Quantity Sold : 12
Unit Price    : $25.50

Revenue = 12 × 25.50
Revenue = $306.00
```

---

## 2. Revenue Per Category

The application calculates the total revenue generated by all products belonging to the same category.

For example:

```text
Electronics : $690.00
Stationery  : $181.25
```

---

## 3. Best-Selling Product

The best-selling product is the product with the highest quantity sold.

Example:

```text
Best-Selling Product : Ballpoint Pen (100 units)
```

---

## 4. Highest-Revenue Product

The highest-revenue product is the product that generates the highest total revenue.

Example:

```text
Highest Revenue : Wireless Mouse ($306.00)
```

---

## 5. Grand Total Revenue

The grand total revenue is calculated by adding the revenue generated by all products.

Example:

```text
Grand Total Revenue : $871.25
```

# Running the Application

The application supports the following command-line format:

```text
java SalesReporter <csv-file-path> <output-method> [output-file-path]
```

Where:

- `<csv-file-path>` is the path to the input CSV file.
- `<output-method>` must be `console` or `file`.
- `[output-file-path]` specifies the output text file when file output is selected.

---

# Console Output

To generate the report in the console:

```text
java SalesReporter products.csv console
```

When running the project through IntelliJ IDEA, an example program argument is:

```text
SENG21222-Assignment/com/sales/products.csv console
```

The generated report will be displayed directly in the console.

---

# File Output

To save the report to a text file:

```text
java SalesReporter products.csv file report.txt
```

An example IntelliJ program argument is:

```text
SENG21222-Assignment/com/sales/products.csv file report.txt
```

The generated report will be written to the specified text file.

---

# Interactive Output Selection

The application also supports interactive output selection when an output method is not supplied.

The following menu is displayed:

```text
============================================
 Select Output Method:
 1. Console Output
 2. File Output
============================================
Enter choice (1 or 2):
```

### Option 1 – Console Output

Entering:

```text
1
```

displays the generated report in the console.

### Option 2 – File Output

Entering:

```text
2
```

allows the report to be generated using the file output strategy.

A custom output file name can be entered, or the default `report.txt` file can be used.

# SOLID Principles

## Single Responsibility Principle

The project separates different responsibilities into dedicated classes.

For example:

- `Product` represents product information.
- `CsvReaderService` handles CSV reading.
- `SalesCalculatorService` performs sales calculations.
- `SalesSummary` stores calculated results.
- `ConsoleOutputStrategy` handles console output.
- `FileOutputStrategy` handles file output.
- `SalesReporter` coordinates the application.

This prevents a single class from being responsible for all application functionality.

---

## Open-Closed Principle

The output functionality is designed around the `OutputStrategy` interface.

Existing output implementations include:

```text
ConsoleOutputStrategy
FileOutputStrategy
```

Additional output methods can be introduced by implementing `OutputStrategy` without changing the main sales calculation logic.

---

# Strategy Design Pattern

The Strategy Design Pattern is used for the report output functionality.

```text
                 OutputStrategy
                       |
             +---------+---------+
             |                   |
             v                   v
ConsoleOutputStrategy    FileOutputStrategy
```

`SalesReporter` selects the appropriate strategy depending on the requested output method.

This keeps the output logic separate from the calculation logic and makes the application easier to extend.
